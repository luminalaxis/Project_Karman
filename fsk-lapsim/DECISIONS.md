# DECISIONS — 설계 결정 기록

형식: **결정 / 고려한 대안 / 근거**. 번호는 진행 순서.

## D-01 저장소 위치와 git
- **결정**: 작업 디렉터리(기존 git 저장소 `LAP_TIME_OPTIMIZATION--AERO`) 안에 `fsk-lapsim/` 하위 디렉터리로 만들고,
  지정 브랜치에 Phase 마다 커밋·푸시한다. 별도 중첩 git 저장소는 만들지 않는다.
- **대안**: `fsk-lapsim/` 안에 `git init` 으로 독립 저장소 생성.
- **근거**: 중첩 저장소는 상위 저장소에서 서브모듈/무시 처리가 필요하고 원격 푸시 경로가 없어 세션이 끊기면 작업이 사라진다.
  하위 디렉터리면 커밋·푸시가 바로 백업이 된다. 최종 zip 은 `fsk-lapsim/` 만 묶는다.

## D-02 기존 `lapsim/` 코드와의 관계
- **결정**: 저장소 루트의 기존 `lapsim/` (이전 세션의 JSON 기반 시뮬레이터)는 건드리지 않고 새 패키지 `fsk_lapsim` 을 처음부터 구현한다.
- **대안**: 기존 코드를 확장.
- **근거**: 지시서가 패키지명·설정 형식(YAML+pydantic)·모델 A/B·검증 항목을 새로 규정했다. 기존 코드의 데이터(아래 D-03)만 재사용한다.

## D-03 FSK 2026 엔듀런스 실측 중심선
- **결정**: 기존 `tracks/fsk_2026_endurance.json` (cone2track 내보내기, 852 점, 850.8 m, 시계방향)의 중심선 x/y 를
  `data/tracks/fsk2026_endurance_centerline.csv` 로 변환해 **참고 트랙**으로 포함한다. 기본 이벤트는 지시서대로 합성 트랙을 쓴다.
- **대안**: 무시 / 기본 엔듀런스 트랙으로 사용.
- **근거**: 지시서는 "실제 FSK 코스 데이터 없음"이라고 했으므로 기본값은 합성 트랙. 그러나 저장소에 이미 있는 실측 기반 데이터는
  CSV 임포트 기능의 실사용 예이자 합성 트랙의 타당성 비교 기준으로 유용하다. 출처·정확도 미확인이라고 명시한다.

## D-04 설정 파일 위치
- **결정**: 예시 설정(YAML)과 데이터(DUMMY CSV, 트랙 CSV, NMEA 예시)는 패키지 안 `src/fsk_lapsim/configs/`, `src/fsk_lapsim/data/` 에 두고
  패키지 데이터로 설치한다. CLI 는 경로 미지정 시 이것을 쓰고, `fsk-lapsim init-configs DIR` 로 편집용 사본을 꺼낼 수 있다.
- **대안**: 저장소 최상위 `configs/` 만 두기 / 두 곳에 복사.
- **근거**: 어디서 실행하든(설치 후 다른 디렉터리) 기본 예제가 동작해야 하고, 사본 두 개는 어긋나기 쉽다.

## D-05 공력 밸런스 정의 (항력 피칭모멘트)
- **결정**: `balance_front` 는 **지면 기준 항력 피칭모멘트를 포함한** 전륜 다운포스 비율로 정의한다 (CFD/풍동 관례).
  차량 모델은 별도 항력 모멘트를 넣지 않고 종방향 하중이동은 m·ax·h/L 만 쓴다. 부품 합성에서는 부품별 z_cp 로
  −CdA·z/L 를 앞축 다운포스에 더해 같은 정의를 만든다.
- **대안**: 항력 작용 높이를 차량 파라미터로 두고 하중이동에 별도 합산.
- **근거**: 지시서 3.3 의 하중이동 식(m·ax·h/L)을 그대로 따르면서도, 리어윙처럼 높은 부품의 항력이 앞축 하중을 빼는 효과를
  부품 합성에서 반영할 수 있다. 두 방식이 섞여 이중 계산되는 것을 막는다.

## D-06 의존성
- **결정**: 런타임 의존성은 numpy, scipy, pandas, matplotlib, pyyaml, pydantic, typer. 개발용으로 pytest, hypothesis, ruff 외에
  **pytest-cov** 를 추가한다.
- **근거**: 지시서 6절이 커버리지 85 % 를 요구하므로 측정 도구가 필요하다. pytest-cov 는 coverage 를 감싼 pytest 플러그인으로 런타임에는 쓰지 않는다.

## D-07 타이어 하중 민감도 상한
- **결정**: F_max(Fz) = μ(Fz)·Fz 가 최대가 되는 하중 Fz_peak = Fz0(1−k)/(−2k) 를 넘으면 F_max 를 그 값으로 고정한다. Fz < 0 은 0.
- **대안**: 선형식을 그대로 사용 (하중이 커지면 힘이 줄어듦) / μ 하한만 두기.
- **근거**: 원식은 Fz > 2683 N 에서 하중을 더 받을수록 힘이 줄어 "ClA↑ → 느려지지 않음" 단조성이 깨지는 비물리적 결과를 낸다.
  기본 차량에서 바퀴 하중은 대부분 이 값 아래라 영향은 작다.

## D-08 코너 한계 ay 의 정의 (일정 속도 유지 상태) — P2 에서 수정
- **결정**: ay_max(v) 는 **속도를 유지할 수 있는 (ax = 0, 구동력이 항력+구름저항을 감당) 최대 횡가속도**.
  최고속도 이상에서는 ax = 최대 출력 시 가속도(음수). 이 기준 상태를 ax_ref 라 하고, |ay| ≤ ay_max 이면 가속/감속 한계는
  항상 ax_ref 를 포함하는 구간 [ax_brk, ax_acc] 가 된다. GGV 의 횡축은 이 ay_max 로 정규화한다.
- **고려한 대안**: (1) 코스팅 상태(타이어 Fx = 0) 기준 — 처음 구현했으나 아래 문제로 폐기.
  (2) 전 GG 포락선의 최대 ay — 최대점에서 ax 가 0 이 아니어서 "감속 한계가 양수" 같은 상태가 생기고 패스 로직이 복잡해짐.
  (3) 전진 패스는 유지 가능 한계, 후진 패스는 코스팅 한계로 따로 클램프 — 동작하지만 정의가 둘이라 혼란.
- **근거**: 코스팅 기준이면 (a) 항력이 있는 긴 정상선회에서 한계점의 가속도가 음수라 Heun 적분이 √(1−u²) 절벽을 넘어
  평형점을 건너뛰고 (b) 후륜이 먼저 한계인 차는 스로틀을 밟으면 하중이동으로 후륜 그립이 늘어 코스팅 한계보다 높은 ay 에서도
  가속이 가능해져 정규화가 모순된다. 일정 속도 기준은 지시서 6-1 해석해(항력 0)와 정확히 같고, 스키드패드(정상선회)와 같은
  정의이며, 한계에서 ax_acc ≥ 0 ≥ ax_brk 라 두 패스가 클램프를 안정적으로 유지한다. 짧은 정점에서 순간적으로 코스팅
  한계까지 쓰는 효과는 무시되므로 아주 약간 보수적이다 (MODEL.md 한계 절).

## D-09 효율의 적용
- **결정**: 지시서 3.5 그대로 휠 구동력 = min(T·G·η/r, P·η/v, 타이어 한계). 회생 시 모터 토크 한계는 T·G/r (η 없이),
  회수 전력은 η·F·v 를 20 kW 로 제한.
- **근거**: 지시서 수식 준수. 구동 시 토크 경로에도 종합 효율을 곱하는 것은 보수적이다 (실제 기어 효율 ~0.97). 문서에 한계로 적는다.

## D-10 회생제동 기본값
- **결정**: 기본 `regen_enabled: true` (20 kW). 엔듀런스 결과에는 회생 포함/미포함 에너지를 모두 보고한다.
- **근거**: 지시서는 "사용 여부는 옵션". FS EV 대부분이 회생을 쓰고, 두 값을 함께 보이면 어느 쪽 가정이든 바로 읽을 수 있다.

## D-11 FSK 규정 웹 검색
- **결정**: 웹 검색으로 FSK 2026 (영광 자동차안전연구원, 43개 대학 58팀) 정보는 확인했지만 트랙 규정 수치는 찾지 못했다.
  FS 규정 PDF 는 네트워크 정책으로 접근 불가. 지시서가 준 FS 일반 범위를 쓰고 "FSK 규정으로 교체 필요"로 표시한다.

## D-12 적분 방식
- **결정**: 전진/후진 패스는 거리 s 에 대해 v² 를 Heun(RK2) 으로 적분 (예측-보정), 한계 속도로 클램프. 시간은
  dt = 2·ds/(v_i + v_{i+1}) (구간 내 등가속 가정, 정지 출발에서도 유한).
- **대안**: 오일러 (1차) / 시간 적분.
- **근거**: v² 는 등가속에서 s 에 선형이라 오차가 작고, 75 m 가속이 solve_ivp 기준과 2e-5 이내, ds 절반 변화 < 1e-4.

## D-13 GGV 격자
- **결정**: 속도는 0.25 m/s 등간격, 횡방향은 ay = sin θ·ay_max(v), θ ∈ [0, π/2] 등간격 73 점. ay_max(v) 는 v² 선형보간.
  솔버 루프는 리스트 기반 순수 파이썬 보간 (numpy 스칼라 호출보다 수십 배 빠름).
- **대안**: ay 등간격 격자 / 매 스텝 직접 계산.
- **근거**: 마찰 타원의 √(1−u²) 는 θ 로는 cos θ 라 매끄러워 한계 근처 보간 오차가 작다. 직접 계산은 스텝당 수 ms (bisection)
  라 랩당 수십 초가 되지만 GGV 보간은 랩당 약 0.05 s.

## D-14 GGV 가속 한계의 분리 저장 (P3)
- **결정**: 가속 한계 = min(전륜 횡그립 한계 표, 후륜 트랙션 한계 표, 파워트레인 한계(닫힌 식)). 표는 제약별로 따로 저장하고
  조회 시 최솟값을 취한다. 속도 격자는 최고속도에서 정확히 끝난다.
- **대안**: 하나의 합성 표 보간 (처음 구현) / θ 격자 세분화만.
- **근거**: 각 제약의 가능 구간이 기준 상태에서 시작하는 구간이므로 최댓값은 제약별 최댓값의 최솟값과 정확히 같다.
  합성 표는 제약이 바뀌는 꺾임점(트랙션↔출력, 트랙션↔전륜 횡그립)에서 선형보간 오차가 생겨 최대 0.69 m/s² (회전수 제한 경계),
  0.057 m/s² (꺾임점) 까지 났다. 분리 후 직접 계산 대비 최대 0.0085 m/s² (모델 B), 0.028 m/s² (모델 A), 99 % 구간 0.002 m/s².
  테스트 9 허용오차는 최대 0.03 m/s² (0.3 % g), 99 백분위 0.005 m/s² 로 정했다.
